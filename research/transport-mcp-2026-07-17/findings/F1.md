# F1: MCP 2025-03-26 Spec & Go Implementations

## Findings

### [1] MCP 2025-03-26 spec defines Streamable HTTP as a single-endpoint transport replacing HTTP+SSE
- quote: "The server MUST provide a single HTTP endpoint path (hereafter referred to as the MCP endpoint) that supports both POST and GET methods. For example, this could be a URL like https://example.com/mcp"
- url: https://modelcontextprotocol.io/specification/2025-03-26/basic/transports
- source_type: primary
- published: 2025-03-26
- confidence: high

### [2] Streamable HTTP uses POST for client-to-server messages and GET for server-initiated SSE streams
- quote: "Every JSON-RPC message sent from the client MUST be a new HTTP POST request to the MCP endpoint. The client MUST include an Accept header, listing both application/json and text/event-stream as supported content types."
- url: https://modelcontextprotocol.io/specification/2025-03-26/basic/transports
- source_type: primary
- published: 2025-03-26
- confidence: high

### [3] Session management uses Mcp-Session-Id header for stateful connections
- quote: "A server using the Streamable HTTP transport MAY assign a session ID at initialization time, by including it in an Mcp-Session-Id header on the HTTP response containing the InitializeResult. The session ID SHOULD be globally unique and cryptographically secure (e.g., a securely generated UUID, a JWT, or a cryptographic hash)."
- url: https://modelcontextprotocol.io/specification/2025-03-26/basic/transports
- source_type: primary
- published: 2025-03-26
- confidence: high

### [4] Resource subscriptions use resources/subscribe with notifications/resources/updated
- quote: "The protocol supports optional subscriptions to resource changes. Clients can subscribe to specific resources and receive notifications when they change: Subscribe Request: {method: 'resources/subscribe', params: {uri: '...'}}, Update Notification: {method: 'notifications/resources/updated', params: {uri: '...'}}"
- url: https://modelcontextprotocol.io/specification/2025-03-26/server/resources
- source_type: primary
- published: 2025-03-26
- confidence: high

### [5] MCP lifecycle: initialize → operation → shutdown with capability negotiation
- quote: "The initialization phase MUST be the first interaction between client and server. During this phase, the client and server: Establish protocol version compatibility, Exchange and negotiate capabilities, Share implementation details. The client MUST initiate this phase by sending an initialize request containing: Protocol version supported, Client capabilities, Client implementation information."
- url: https://modelcontextprotocol.io/specification/2025-03-26/basic/lifecycle
- source_type: primary
- published: 2025-03-26
- confidence: high

### [6] mark3labs/mcp-go: 8.9k stars, v0.56.0, supports Streamable HTTP + SSE + stdio transports
- quote: "MCP-Go supports stdio, SSE and streamable-HTTP transport layers. For SSE transport, you can use SetConnectionLostHandler() to detect and handle disconnections for implementing reconnection logic."
- url: https://github.com/mark3labs/mcp-go
- source_type: primary
- published: 2026-07-09
- confidence: high

### [7] mark3labs/mcp-go: full session management with per-session tools and tool filtering
- quote: "MCP-Go provides a robust session management system that allows you to: Maintain separate state for each connected client, Register and track client sessions, Send notifications to specific clients, Provide per-session tool customization"
- url: https://github.com/mark3labs/mcp-go
- source_type: primary
- published: 2026-07-09
- confidence: high

### [8] Official MCP Go SDK exists: modelcontextprotocol/go-sdk, 4.8k stars, maintained with Google
- quote: "This repository contains an implementation of the official Go software development kit (SDK) for the Model Context Protocol (MCP). The SDK endeavors to implement the full MCP spec."
- url: https://github.com/modelcontextprotocol/go-sdk
- source_type: primary
- published: 2026-05-22
- confidence: high

### [9] Official Go SDK supports MCP spec versions 2024-11-05 through 2025-11-25
- quote: "mcp-go implements the Model Context Protocol specification version 2025-11-25, with backward compatibility for versions 2025-06-18, 2025-03-26, and 2024-11-05."
- url: https://github.com/modelcontextprotocol/go-sdk
- source_type: primary
- published: 2026-05-22
- confidence: high

### [10] Streamable HTTP supports resumability via SSE event IDs and Last-Event-ID header
- quote: "Servers MAY attach an id field to their SSE events. If the client wishes to resume after a broken connection, it SHOULD issue an HTTP GET to the MCP endpoint, and include the Last-Event-ID header to indicate the last event ID it received."
- url: https://modelcontextprotocol.io/specification/2025-03-26/basic/transports
- source_type: primary
- published: 2025-03-26
- confidence: high

### [11] DNS rebinding protection: servers MUST validate Origin header
- quote: "Servers MUST validate the Origin header on all incoming connections to prevent DNS rebinding attacks. When running locally, servers SHOULD bind only to localhost (127.0.0.1) rather than all network interfaces (0.0.0.0)."
- url: https://modelcontextprotocol.io/specification/2025-03-26/basic/transports
- source_type: primary
- published: 2025-03-26
- confidence: high

### [12] Server capabilities: resources can declare subscribe and listChanged independently
- quote: "Servers that support resources MUST declare the resources capability. The capability supports two optional features: subscribe: whether the client can subscribe to be notified of changes to individual resources. listChanged: whether the server will emit notifications when the list of available resources changes. Both subscribe and listChanged are optional—servers can support neither, either, or both."
- url: https://modelcontextprotocol.io/specification/2025-03-26/server/resources
- source_type: primary
- published: 2025-03-26
- confidence: high
