# F5: Native MCP Server Design in Go

## Findings

### [1] mark3labs/mcp-go is the dominant Go MCP library (8.9k stars, v0.56.0, 563 commits, 1.6k importers)
- quote: "A Go implementation of the Model Context Protocol (MCP), enabling seamless integration between LLM applications and external data sources and tools."
- url: https://github.com/mark3labs/mcp-go
- source_type: primary
- published: 2026-07-09 (v0.56.0 release)
- confidence: high

### [2] mcp-go implements MCP spec 2025-11-25 with backward compatibility for 2024-11-05, 2025-03-26, and 2025-06-18
- quote: "mcp-go implements the Model Context Protocol specification version 2025-11-25, with backward compatibility for versions 2025-06-18, 2025-03-26, and 2024-11-05."
- url: https://github.com/mark3labs/mcp-go
- source_type: primary
- published: 2026-07-09
- confidence: high

### [3] StreamableHTTPServer implements http.Handler and can be mounted on any net/http router (chi, gorilla/mux, ServeMux)
- quote: "StreamableHTTPServer is an http.Handler, so it can be mounted in any router that speaks net/http."
- url: https://github.com/mark3labs/mcp-go
- source_type: primary
- published: 2026-07-09
- confidence: high

### [4] Tools are defined declaratively with schema builders and registered with handler functions
- quote: "tool := mcp.NewTool("hello_world", mcp.WithDescription("Say hello to someone"), mcp.WithString("name", mcp.Required(), mcp.Description("Name of the person to greet")))"
- url: https://github.com/mark3labs/mcp-go
- source_type: primary
- published: 2026-07-09
- confidence: high

### [5] Per-session tools support dynamic tool surfaces via SessionWithTools interface, AddSessionTool/DeleteSessionTools, and ToolFilterFunc
- quote: "For more advanced use cases, you can implement the SessionWithTools interface to support per-session tool customization... err := s.AddSessionTool(advSession.SessionID(), userSpecificTool, func(ctx context.Context, req mcp.CallToolRequest) (*mcp.CallToolResult, error) {...})"
- url: https://github.com/mark3labs/mcp-go
- source_type: primary
- published: 2026-07-09
- confidence: high

### [6] Tool filtering at list-time lets the server dynamically control which tools each session sees based on context/session state
- quote: "Add a tool filter that only shows tools with certain prefixes... s := server.NewMCPServer(..., server.WithToolFilter(func(ctx context.Context, tools []mcp.Tool) []mcp.Tool { session := server.ClientSessionFromContext(ctx) ... }))"
- url: https://github.com/mark3labs/mcp-go
- source_type: primary
- published: 2026-07-09
- confidence: high

### [7] MCP spec defines Streamable HTTP: single endpoint handles POST (client→server) and GET (SSE server→client push), with session management via Mcp-Session-Id header
- quote: "The server MUST provide a single HTTP endpoint path (hereafter referred to as the MCP endpoint) that supports both POST and GET methods... The client MAY issue an HTTP GET to the MCP endpoint. This can be used to open an SSE stream, allowing the server to communicate to the client, without the client first sending data via HTTP POST."
- url: https://modelcontextprotocol.io/specification/2025-03-26/basic/transports
- source_type: primary
- published: unknown (spec page)
- confidence: high

### [8] StreamableHTTPServer supports both standalone Start() and embedding via ServeHTTP for integration with existing HTTP servers
- quote: "mux.Handle("/mcp", server.NewStreamableHTTPServer(s))... Add custom HTTP endpoints alongside MCP: mux.HandleFunc("/api/status", handleStatus)"
- url: https://mcp-go.dev/transports/http
- source_type: primary
- published: unknown
- confidence: high

### [9] mcp-go supports three transport layers: stdio, SSE, and Streamable HTTP; StreamableHTTP replaces the old HTTP+SSE from spec 2024-11-05
- quote: "MCP-Go supports stdio, SSE and streamable-HTTP transport layers."
- url: https://github.com/mark3labs/mcp-go
- source_type: primary
- published: 2026-07-09
- confidence: high

### [10] Server-to-client notifications are supported via SendNotificationToSpecificClient and SendNotificationToAllClients
- quote: "err := s.SendNotificationToSpecificClient(session.SessionID(), "notification/update", map[string]any{"message": "New data available!"})"
- url: https://github.com/mark3labs/mcp-go
- source_type: primary
- published: 2026-07-09
- confidence: high

### [11] metoro-io/mcp-golang is an alternative Go MCP library (1.2k stars, v0.16.1) with type-safe struct-based tool arguments but less mature Streamable HTTP support
- quote: "mcp-golang is an unofficial implementation of the Model Context Protocol in Go. Write MCP servers and clients in golang with a few lines of code."
- url: https://github.com/metoro-io/mcp-golang
- source_type: primary
- published: 2026-02-25 (v0.16.1)
- confidence: high

### [12] mcp-go's framework-agnostic Handle() entry point enables embedding in non-net/http frameworks (fasthttp, fiber) with a custom HTTPResponseWriter interface
- quote: "StreamableHTTPServer exposes two equivalent entry points: ServeHTTP(w http.ResponseWriter, r *http.Request) — the standard net/http handler... Handle(w HTTPResponseWriter, r *HTTPRequest) — a transport-agnostic entry point"
- url: https://mcp-go.dev/transports/http
- source_type: primary
- published: unknown
- confidence: high
