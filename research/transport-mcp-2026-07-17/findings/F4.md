# F4: External MCP Adapter Pattern for Games

## Findings

### [1] minecraft-mcp-server (yuniko-software, 662 stars) uses the external adapter pattern: an MCP server wraps Mineflayer (a Minecraft bot client library) to control a character as a regular player, with the game server unaware it's talking to an AI.
- quote: "A Minecraft bot powered by large language models and Mineflayer API. This bot uses the Model Context Protocol (MCP) to enable Claude and other supported models to control a Minecraft character."
- url: https://github.com/yuniko-software/minecraft-mcp-server
- source_type: primary
- published: 2026-02-26 (latest release v2.0.4)
- confidence: high

### [2] The external adapter's architecture separates MCP tool registration (ToolFactory) from game client connection (BotConnection), with automatic reconnection: every tool call first checks connection state and attempts reconnect if disconnected, polling up to reconnectDelayMs+5000ms.
- quote: "registerTool(...) { this.server.tool(name, description, schema, async (args) => { const connectionCheck = await this.connection.checkConnectionAndReconnect(); if (!connectionCheck.connected) { return { content: [...], isError: true }; } ... }); }"
- url: https://github.com/yuniko-software/minecraft-mcp-server/blob/main/src/tool-factory.ts
- source_type: primary
- published: 2026-02-26
- confidence: high

### [3] minecraft-mcp-server exposes ~20 tools organized by category (Movement, Flight, Inventory, Block Interaction, Entity, Communication, Game State) — all are imperative commands ("move-to-position", "dig-block", "send-chat") not semantic actions, meaning the LLM must compose multi-step plans from primitives.
- quote: "Available Commands: Movement - get-position, move-to-position, look-at, jump, move-in-direction; Flight - fly-to; Inventory - list-inventory, find-item, equip-item; Block Interaction - place-block, dig-block, get-block-info, find-blocks"
- url: https://github.com/yuniko-software/minecraft-mcp-server
- source_type: primary
- published: 2026-02-26
- confidence: high

### [4] FundamentalLabs/minecraft-mcp (74 stars) takes a higher-level approach with 30 "verified skills" (joinGame, mineResource, craftItems, harvestMatureCrops, etc.) that encapsulate multi-step game logic, plus multi-bot management — demonstrating that external adapters can abstract above raw game commands.
- quote: "30 Verified Skills: Pre-built, tested skills for common Minecraft tasks... Multi-Bot Support: Manage multiple bots simultaneously"
- url: https://github.com/FundamentalLabs/minecraft-mcp
- source_type: primary
- published: unknown
- confidence: high

### [5] Nexlen/mud-mcp (32 stars) implements MCP 2025-03-26 natively — the game server IS the MCP server, exposing tools (look, move, pick_up, battle), prompts (room_description, quest_prompt, battle_prompt), and resources (mud://world, mud://room/current, mud://player/inventory) with dynamic availability driven by game state.
- quote: "The server provides context-sensitive tools that appear and disappear based on your current situation. Tools include look, move, inventory, take, battle, and talk. Each tool uses proper input schemas and annotations, with some tools only becoming available when relevant."
- url: https://github.com/Nexlen/mud-mcp
- source_type: primary
- published: unknown
- confidence: high

### [6] Native MCP integration enables real-time event notifications that external adapters cannot easily replicate: mud-mcp sends tools/list_changed, prompts/list_changed, and resources/changed notifications as game state evolves, so the MCP client's available actions update reactively without polling.
- quote: "When a player's state changes (e.g., entering a new room, picking up an item), the server sends notifications/tools/list_changed notifications to update available actions... examples of dynamic tool availability: open_chest appears only when the player is in a room with a chest, battle becomes available when monsters are present"
- url: https://raw.githubusercontent.com/Nexlen/mud-mcp/main/spec.md
- source_type: primary
- published: unknown
- confidence: high

### [7] EllyMUD (6 stars) takes a hybrid approach: it's a full MUD with Telnet/WebSocket clients AND a native MCP server on port 3100 with API-key auth, exposing read-only game state queries plus "virtual sessions" that let AI agents send commands and receive output — bridging external adapter and native integration.
- quote: "MCP server: Model Context Protocol on port 3100 for AI integration and headless testing... virtual_session_create: Create a virtual AI gameplay session... virtual_session_send_command: Send command to virtual session"
- url: https://github.com/ellyseum/ellymud
- source_type: primary
- published: 2026-05-04
- confidence: high

### [8] The key limitation of external adapters is they can only observe what a normal player observes — no privileged access to game internals, no ability to modify game state directly, and text output must be parsed (for MUDs, this means ANSI-stripped text parsing). Native integration exposes structured data via resources.
- quote: "All endpoints provide read-only views of game state... Live Data: Access to runtime state (online users, active combat); Static Data: Access to configuration (rooms, items, NPCs)"
- url: https://raw.githubusercontent.com/ellyseum/ellymud/main/docs/architecture.md
- source_type: primary
- published: 2026-05-04
- confidence: high

### [9] EllyMUD's MCP server uses 256-bit API keys (64 hex chars) stored in .env, validates on all requests except /health, and logs all requests with IP addresses — establishing an auth pattern for game MCP servers that need to distinguish AI agents from human players.
- quote: "256-bit API keys (64 hex characters)... Key validation on all requests (except /health)... Keys stored in .env (not version controlled)... All requests logged with IP addresses"
- url: https://raw.githubusercontent.com/ellyseum/ellymud/main/docs/api-reference.md
- source_type: primary
- published: 2026-05-04
- confidence: high

### [10] Nexlen/mud-mcp implements MCP sampling — the server can request AI-generated content FROM the client (e.g., asking Claude to generate NPC dialogue), creating a bidirectional AI loop where the game engine and LLM collaborate on content generation rather than the LLM just executing commands.
- quote: "MCP Sampling allows the server to request AI assistance from compatible clients (like Claude Desktop) to generate dynamic content in real-time. Instead of pre-written responses, your adventure becomes a collaborative storytelling experience between the game engine and AI."
- url: https://github.com/Nexlen/mud-mcp
- source_type: primary
- published: unknown
- confidence: high

### [11] For Dark Pawns, the external adapter pattern (MCP server wrapping a telnet client) is the fastest path because it requires zero changes to the game server, but it cannot expose structured resources or send proactive notifications — the adapter can only react to tool calls and parse text output.
- quote: "Transport Options: The server supports multiple transports: stdio (for command-line integration), HTTP with SSE (for web clients)"
- url: https://github.com/Nexlen/mud-mcp
- source_type: primary
- published: unknown
- confidence: high
