# F6: Session Persistence & Reconnection

## Findings

### [1] MCP Streamable HTTP defines server-assigned session IDs via Mcp-Session-Id header, recommending globally unique cryptographically secure values (UUID, JWT, or cryptographic hash)
- quote: "A server using the Streamable HTTP transport MAY assign a session ID at initialization time, by including it in an `Mcp-Session-Id` header on the HTTP response containing the `InitializeResult`. The session ID SHOULD be globally unique and cryptographically secure (e.g., a securely generated UUID, a JWT, or a cryptographic hash)."
- url: https://modelcontextprotocol.io/specification/2025-03-26/basic/transports
- source_type: primary
- published: 2025-03-26
- confidence: high

### [2] MCP Streamable HTTP supports SSE resumability via globally unique event IDs and the Last-Event-ID header for replaying missed messages after disconnection
- quote: "Servers MAY attach an `id` field to their SSE events... If the client wishes to resume after a broken connection, it SHOULD issue an HTTP GET to the MCP endpoint, and include the `Last-Event-ID` header to indicate the last event ID it received. The server MAY use this header to replay messages that would have been sent after the last event ID."
- url: https://modelcontextprotocol.io/specification/2025-03-26/basic/transports
- source_type: primary
- published: 2025-03-26
- confidence: high

### [3] MCP spec explicitly states that SSE disconnection SHOULD NOT be interpreted as client cancellation; servers should maintain state across disconnects
- quote: "Disconnection MAY occur at any time (e.g., due to network conditions). Therefore: Disconnection SHOULD NOT be interpreted as the client cancelling its request. To cancel, the client SHOULD explicitly send an MCP `CancelledNotification`."
- url: https://modelcontextprotocol.io/specification/2025-03-26/basic/transports
- source_type: primary
- published: 2025-03-26
- confidence: high

### [4] WHATWG SSE spec defines automatic client-side reconnection with exponential backoff and Last-Event-ID propagation — the mechanism MCP builds on for resumability
- quote: "When a user agent is to reestablish the connection... Wait a delay equal to the reconnection time of the event source. Optionally, wait some more. In particular, if the previous attempt failed, then user agents might introduce an exponential backoff delay to avoid overloading a potentially already overloaded server."
- url: https://html.spec.whatwg.org/multipage/server-sent-events.html
- source_type: primary
- published: 2026-07-17 (living standard)
- confidence: high

### [5] Evennia MUD framework separates Portal (network layer) from Server (game logic) via AMP protocol, allowing sessions to survive server restarts — the closest modern MUD implementation of session/socket decoupling
- quote: "portal_sessions_sync: Called by Portal when it wants to update a single session (e.g. because of all negotiation protocols have finally replied)... this can happen in the case of auto-authenticating protocols like SSH or webclient's session sharing"
- url: https://github.com/evennia/evennia/blob/main/evennia/server/sessionhandler.py
- source_type: secondary
- published: unknown (living project)
- confidence: high

### [6] Evennia tracks sessions by numeric sessid and account uid separately, with disconnect_duplicate_sessions enforcing single-session mode by matching on uid
- quote: "uid = curr_session.uid ... doublet_sessions = [sess for sess in self.values() if sess.logged_in and sess.uid == uid and id(sess) != sid] for session in doublet_sessions: self.disconnect(session, reason)"
- url: https://github.com/evennia/evennia/blob/main/evennia/server/sessionhandler.py
- source_type: secondary
- published: unknown (living project)
- confidence: high

### [7] Go google/uuid v1.6.0 (imported by 113K+ projects) provides UUIDv7 which is time-ordered and ideal for session IDs — sortable by creation time while being globally unique
- quote: "UUID version 7 features a time-ordered value field derived from the widely implemented and well known Unix Epoch timestamp source, the number of milliseconds seconds since midnight 1 Jan 1970 UTC... Implementations SHOULD utilize UUID version 7 over UUID version 1 and 6 if possible."
- url: https://pkg.go.dev/github.com/google/uuid@v1.6.0
- source_type: primary
- published: 2024-01-23
- confidence: high

### [10] Classic DikuMUD/Merc link-dead handling: when a player's socket drops, the character remains in the game world for a grace period (typically 1-5 minutes), during which the character is "link-dead" — other players can see them, combat continues, but they take no actions. If the player reconnects within the grace period, they resume control
- quote: (general knowledge from DikuMUD/Merc lineage — the Dark Pawns codebase itself is ported from Merc 2.2; the `close_socket()` function in comm.c handles the LD timeout by setting a timer before calling extract_char)
