# F2: WebSocket-Telnet Binary Bridging in Go

## Findings

### [1] coder/websocket provides a first-class NetConn() adapter that converts *websocket.Conn into net.Conn, explicitly designed for tunneling arbitrary protocols over WebSocket binary frames.
- quote: "NetConn converts a *websocket.Conn into a net.Conn. It's for tunneling arbitrary protocols over WebSockets. Few users of the library will need this but it's tricky to implement correctly and so provided in the library."
- url: https://pkg.go.dev/github.com/coder/websocket#NetConn
- source_type: primary
- published: 2026-06-15 (v1.8.15)
- confidence: high

### [2] gorilla/websocket does NOT provide a net.Conn adapter wrapping WebSocket frames — its NetConn() (v1.5.1) and deprecated UnderlyingConn() return the raw underlying TCP connection, with a warning that direct I/O corrupts the WebSocket state.
- quote: "NetConn returns the underlying connection that is wrapped by c. Note that writing to or reading from this connection directly will corrupt the WebSocket connection."
- url: https://pkg.go.dev/github.com/gorilla/websocket@v1.5.3#Conn.NetConn
- source_type: primary
- published: 2024-06-14 (v1.5.3)
- confidence: high

### [3] The coder/websocket NetConn adapter was motivated by recurring requests on the gorilla/websocket tracker (issues #282 and #441) where users wanted a net.Conn-compatible wrapper for protocol tunneling, which gorilla never implemented.
- quote: "Was going through some random reading and I noticed this is an issue that appeared multiple times on the gorilla/websocket tracker: gorilla/websocket#282, gorilla/websocket#441"
- url: https://github.com/coder/websocket/issues/100
- source_type: primary
- published: 2019-06-24
- confidence: high

### [4] coder/websocket's NetConn implementation uses MessageBinary type for writes, disables the read limit (-1), translates StatusNormalClosure/StatusGoingAway to io.EOF, and closes with StatusUnsupportedData if a message of the wrong type arrives — making it safe for raw telnet byte streams.
- quote: "Every Write to the net.Conn will correspond to a message write of the given type on *websocket.Conn. ... If a message is read that is not of the correct type, the connection will be closed with StatusUnsupportedData and an error will be returned. ... the ReadLimit is set to -1 to disable it."
- url: https://raw.githubusercontent.com/coder/websocket/master/netconn.go
- source_type: primary
- published: 2026-06-15
- confidence: high

### [5] The NetConn deadline implementation uses time.AfterFunc timers that cancel internal contexts when deadlines fire while a goroutine is blocked — meaning deadline behavior differs from typical net.Conn (connection is closed on timeout, not just the goroutine interrupted).
- quote: "When a deadline is hit and there is an active read or write goroutine, the connection will be closed. This is different from most net.Conn implementations where only the reading/writing goroutines are interrupted but the connection is kept alive."
- url: https://pkg.go.dev/github.com/coder/websocket#NetConn
- source_type: primary
- published: 2026-06-15
- confidence: high

### [6] coder/websocket supports full RFC 7692 permessage-deflate with both context takeover and no-context-takeover modes, while gorilla/websocket only supports no-context-takeover. Both default to compression disabled.
- quote: "Full permessage-deflate compression extension support — Gorilla only supports no context takeover mode"
- url: https://github.com/coder/websocket (README comparison section)
- source_type: primary
- published: 2026-06-15
- confidence: high

### [7] The Dark Pawns handleConn signature accepts net.Conn directly — `handleConn(rawConn net.Conn, manager *session.Manager, banLevel int)` — making it immediately compatible with a coder/websocket NetConn adapter without any refactoring of the telnet handler internals.
- quote: "func handleConn(rawConn net.Conn, manager *session.Manager, banLevel int) { tc := &telnetConn{ Conn: rawConn, ... }"
- url: file:///Users/zach/.openclaw/workspace/darkpawns_repo/pkg/telnet/listener.go:261
- source_type: primary (project source)
- published: N/A
- confidence: high

### [8] Dark Pawns telnet handler offers MCCP2 (IAC WILL COMPRESS2) during initial negotiation and uses compress/zlib for the compressed stream. A WS bridge must suppress this offer on the WS path since WebSocket clients use permessage-deflate (RFC 7692), not MCCP2.
- quote: "tc.write([]byte{IAC, WILL, OPT_COMPRESS2})" ... "enableCompression starts MCCP2 compression. It sends the COMPRESS_START sequence uncompressed and then wraps subsequent writes in a zlib deflater."
- url: file:///Users/zach/.openclaw/workspace/darkpawns_repo/pkg/telnet/listener.go:283,865
- source_type: primary (project source)
- published: N/A
- confidence: high

### [9] For the WS-to-telnet bridge, binary WebSocket frames (MessageBinary = 2) are the correct frame type for raw telnet bytes, since telnet IAC sequences and ANSI escapes are arbitrary byte sequences, not valid UTF-8 text.
- quote: "TextMessage denotes a text data message. The text message payload is interpreted as UTF-8 encoded text data. ... BinaryMessage denotes a binary data message."
- url: https://pkg.go.dev/github.com/gorilla/websocket#pkg-constants
- source_type: primary
- published: 2024-06-14
- confidence: high

### [10] coder/websocket (v1.8.15, June 2026) is actively maintained by Coder with zero dependencies, zero-alloc reads/writes, concurrent write support, and 5.3k GitHub stars — making it a production-viable choice over the deprecated nhooyr.io/websocket module path.
- quote: "Coder now maintains this project as explained in this blog post. We're grateful to nhooyr for authoring and maintaining this project from 2019 to 2024."
- url: https://github.com/coder/websocket
- source_type: primary
- published: 2026-06-15
- confidence: high

## Dead ends
- Web search was unavailable during this research session; all findings came from direct fetches of known primary sources (pkg.go.dev, GitHub repos, raw source files).
- No real-world examples of Go MUD servers bridging WebSocket to telnet were found in the sources accessed; the pattern is inferred from the library capabilities and the existing handleConn signature.

## Suggested follow-ups
- How to conditionally suppress MCCP2 offer in handleConn when the connection is a WS adapter (flag vs. interface type assertion on telnetConn).
- Whether permessage-deflate context takeover is safe for MUD traffic patterns (small frequent messages vs. large bursts).
- Whether the coder/websocket NetConn deadline-on-timeout behavior (closes connection) is acceptable for long-lived MUD sessions, or if a custom adapter with softer deadline semantics is needed.
