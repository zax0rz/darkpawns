**Author:** Claude, in Zach's session, written on 2026-11-16 after Hydrogen received its brief (`~/PROMPT-2026-11-16-hydrogen-17.md`) and before any of its results. The predictions section is not edited afterwards. Results are appended below it.

## Why this cohort

The v2 slop table ([`README.md`](README.md)) codes mistakes that were *caught and fixed*, mostly through player-visible divergences the oracle or a player found. L5 is a different population: Go code an agent wrote that **C never had, and that no player ever sees**. That's dead specials, an unwired admin command set, invented fallback text behind unreachable branches, a second equipment slot numbering, and money as a synthetic `VNum -1` object. The differential oracle can't see any of it by construction, because none of it prints. It surfaced only through probes and audits:
* Luna's PF-102 blind probes (DP-1476);
* the round-three mutation sample (DP-1512, PF-117);
* the `pkg/spells` test audit (DP-1459, PF-107);
* older fidelity findings (DP-1157, DP-1132).

The 2026-11-15 all-printing mutation sample (PF-123) then landed on this class twice: unwired `AdminCommands.cmdListReports` and an unreachable `CmdShoot` guard. Each such site adds a mutant the census can't kill, so invisible slop also pulls the completion bar's kill rate down.

The five items are the frozen L5 list (`docs/research/frozen-lists-2026-11-11/L2-L4-L5-linear.tsv`): DP-1476, DP-1512, DP-1459, DP-1157 and DP-1132.

- **Q2, invisible:** items 1–3 (DP-1476, DP-1512, DP-1459) are pure deletions with no player-visible change. Their targeted censuses stay clean.
- **Q3, not entirely dead:** at least one of the five turns out not to be dead. Removing it changes output or reveals a live divergence, so the agent has to stop and report instead of deleting. Most likely DP-1157 (slot numbering) or DP-1132 (money), which reach equipment and money everywhere.
- **Q4, categories:** most rows code as Pan **B4, "Inclusion of logic not in the source"**. The dual slot numbering and the synthetic money object fit no Pan category. They're a *duplicate or substitute representation* of something C models once, a candidate new category next to "semantic paraphrase" and "scenario-fitted special case".
- **Q5, births:** most of the code was born before the oracle (2026-07-12), with author `unknown` or one of the early heavy porters (GLM, Codex), in line with v2's 46.8% lower bound.
- **Q6, lifetime:** median lifetime from birth to removal over 100 days, longer than v2's 80.5-day median, because nothing player-visible pointed at it.
- **Q7, caught by:** none of the five was first caught by a census divergence. All came from probes, audits or mutation samples.

**Births:** 10 of the 11 rows were born between 2026-04-17 and 2026-04-26, the first ten days of the port; L011 was born on 2026-07-13. 9 were committed under the repository owner's identity with no agent trace (`unknown`), and 2 by the Brenda agent persona (BRENDA69, model unknown). `cmdBroadcast` (L007) shares its birth commit `070dfe54e` with the yank paraphrase (S001). **Lifetimes:** 126 to 213 days; median **206 days** (v2 median: at least 80.5). **Caught by:** all 11 by audit (probes, mutation samples, the `pkg/spells` test audit), none by a census divergence.

**Why the dead-code ratchet missed them** (from #2738): `deadcode -test` treats tests as roots, so code reached only by its own unit tests counts as live (`CmdSkills`, `AdminCommands`, `doDamage`). Specials registered by `RegisterSpec` inside `init()` escape function-level analysis. And unreachable branches inside live functions are below its resolution. The ratchet baseline fell from 50 to 35.

**Two surprises:**
- **The DP-1132 premise was wrong.** The issue called money as a `VNum -1` object a band-aid. C's `create_money` also yields an object with vnum -1. Only the guard Go added on top of it was invented.
- **L011 was live, not dead.** C's `has_key` has no guard (`src/act.movement.c:428-441`), and C checks for a keyhole only on `pick`. So in C a mortal carrying any vnum -1 object (a corpse, a mail note) can unlock a keyless locked door. Go's guard was born the day after the oracle went live, as a fix for a symptom (a coin pile matching a keyless lock), and removing it restores the C quirk.
