## Why this cohort

The v2 slop table ([`README.md`](README.md)) codes mistakes that were *caught and fixed*, mostly through player-visible divergences the oracle or a player found. L5 is a different population: Go code an agent wrote that **C never had, and that no player ever sees**. That's dead specials, an unwired admin command set, invented fallback text behind unreachable branches, a second equipment slot numbering, and money as a synthetic `VNum -1` object. The differential oracle can't see any of it by construction, because none of it prints. It surfaced only through probes and audits:
* Luna's PF-102 blind probes (DP-1476);
* the round-three mutation sample (DP-1512, PF-117);
* the `pkg/spells` test audit (DP-1459, PF-107);
* older fidelity findings (DP-1157, DP-1132).

The 2026-11-15 all-printing mutation sample (PF-123) then landed on this class twice: unwired `AdminCommands.cmdListReports` and an unreachable `CmdShoot` guard. Each such site adds a mutant the census can't kill, so invisible slop also pulls the completion bar's kill rate down.

The five items are the frozen L5 list (`docs/research/frozen-lists-2026-11-11/L2-L4-L5-linear.tsv`): DP-1476, DP-1512, DP-1459, DP-1157 and DP-1132.

- **Q4, categories:** most rows code as Pan **B4, "Inclusion of logic not in the source"**. The dual slot numbering and the synthetic money object fit no Pan category. They're a *duplicate or substitute representation* of something C models once, a candidate new category next to "semantic paraphrase" and "scenario-fitted special case".

- **Q6, lifetime:** median lifetime from birth to removal over 100 days, longer than v2's 80.5-day median, because nothing player-visible pointed at it.
- **Q7, caught by:** none of the five was first caught by a census divergence. All came from probes, audits or mutation samples.
