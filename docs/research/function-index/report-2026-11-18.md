# C→Go function index: Phase 2 baseline (2026-11-18)

## Scope and method

This report and its two TSV inventories are a citation-backed audit, not a claim that every association is a complete or faithful port. The index contains every named Go function declaration and method (`*ast.FuncDecl`) under `pkg/`; its C edge comes only from the declaration’s Go doc comment. Accepted forms include `src/file.c:line[-end]`, `C equivalent: name()`, `C: name()`, `C name()`, `C’s name()`, `Ported from`, `ports`, `mirrors`, `SPECIAL`/`ASPELL`/`ACMD`, and file-qualified function names. Explicit negative references such as “NOT C’s fname()” are excluded. Test functions are in `index.tsv` but are not counted as production Go ports.

The C parser strips comments and strings, recognizes `ACMD`, `SPECIAL`, `ASPELL`, and plain function definitions, and handles conditional arms. The raw-source validation test compares definitions visible in all source arms; C reference-site counts scan comments/strings out of all arms. The parser does not inspect headers or infer a port from similar names. `go_name_candidates` is a separate, normalized-name-only search and never creates a port edge.

## Counts

- Go named function declarations indexed: **12,142** (including tests). Rows with a resolved citation: **1,516**.
- C function bodies parsed from `src/*.c`: **1,229**. **620** have at least one production Go doc citation; **609** do not.
- Production mapping edges: **1,159** across **620** C functions. **227** C functions have multiple Go associations (**539** additional associations). These are cite edges, not 227 proven duplicate implementations.
- Unresolved C line-citation occurrences: **47** in **46** Go declarations, representing **35** distinct citation/error strings. All could be parsed source files; the cited ranges intersect no parsed C function body except one stale range corrected in this PR.

## Multiple Go associations for one C function

The complete per-C list, C definition lines, each Go file/line/symbol, and non-definition C reference sites are in [`c-functions.tsv`](c-functions.tsv). The table below classifies every multi-association row. “Split/shared” means the functions point to a C routine through separate implementation slices, wrappers, entry points, or call sites; it is not an oracle proof. I compared Go bodies for exact duplicates across these associations and followed the helper/caller paths for the repeated primitive families. Exact-body equality alone cannot catch every semantic clone.
