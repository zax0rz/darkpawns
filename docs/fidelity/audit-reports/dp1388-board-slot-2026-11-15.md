# DP-1388 — the empty-headline board slot is C parity

DP-1388 reports that `pkg/boards/boards.go` `WriteMessage` leaks a storage slot
when the headline is empty: `findSlot` marks the slot taken before the headline
is validated. Grepping C this session shows the same order and the same leak.

## C order (`src/boards.c`)

1. `Board_write_message` (`:213`) checks the write level and the board's
   message count.
2. `NEW_MSG_INDEX(...).slot_num = find_slot()` (`:225`); `find_slot`
   (`:115-125`) sets `msg_storage_taken[i] = 1` before returning.
3. Only then does it skip spaces, truncate the headline at 81 bytes, and test
   `if (!*arg) { send_to_char("We must have a headline!\r\n", ch); return; }`
   (`:234-239`).

The early return leaves the slot marked. A C server leaks one of the 725
storage slots per empty headline until restart, exactly as the port does.

## Port

`WriteMessage` has the same order and messages, and the existing
`boards-depth` witness (`boards.write-empty-headline`) is green. The new
`TestWriteMessageEmptyHeadlineKeepsCAllocationOrder` pins the allocation order:
the empty headline consumes slot 0, the next post takes slot 1. If a future
approved divergence releases the slot (a fix for C's leak), that test must
change deliberately; R1/R4 do not let the port silently diverge.

## Ruling needed

DP-1388 is not a port regression. Close it as C parity, or approve a
divergence that releases the slot and record it `divergent-approved`.
