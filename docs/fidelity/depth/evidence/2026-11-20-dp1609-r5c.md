# DP-1609 R5c audit

## Silken missile dispatch

`src/spells.c:883-912` defines `spell_silken_missile`; `src/spells.h:373` only
declares it. A source-wide search found no other C reference to the routine.
The C manual-spell dispatcher at `src/spell_parser.c:517-530` has no silken
missile arm, the `spello()` table has no registration, and there is no
`SPELL_SILKEN_MISSILE` constant. A quoted player cast therefore reaches the
unknown-spell return at `src/spell_parser.c:978-988` before a spell body can
run. The direct C body remains an excluded orphan, while the Go-only ID 200
constant, manual dispatch arm, and implementation are removed.

## Fixed object-pronoun class

A balanced-parenthesis scan of `src/*.c` enumerated 88 direct `act()` calls
whose template contains `$p` and whose audience includes `TO_CHAR`. The Go
player-output search found no other spell path replacing the object's `$p`
short-description substitution with a fixed `it` where the object itself is
being introduced. The other matching phrases are referential wording after an
object has already been named (for example, “let go of it”) or a separate
held-container refusal; their C call paths retain their own wording and are
not substitutes for `$p`. No second silken-style candidate was found in the
spell surface. This audits the behavior class under R5c; it does not change
the oracle or the governing rulebook.

## Mounted death-trap output

The C death-trap caller invokes `death_cry(mount)` before extraction
(`src/act.movement.c:296-300`). `death_cry` emits a room `act()` with `$n` and
then the adjacent-room “someone's death cry” act (`src/fight.c:506-529`). Go
now accepts either `Player` or `MobInstance` in `deathCry` and uses the same
room and open-adjacent-room delivery for the mount. The live scenario is
`death-trap-mounted-mount-deathcry-depth.txt`.
