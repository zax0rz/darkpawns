## Design decision: complete C ID-based sweep

The parent remains blocked. The whole C function compares IDNUM, closes every duplicate descriptor, then scans character_list for descriptorless bodies and deletes extra copies. Go's current implementation uses one exact name-key lookup. Three fail-capable negative controls (experimental-dupe-id.go.fixture) demonstrate: same name/different ID wrongly adopts the old body; same ID/folded registry key misses it; a world body without a retained session is ignored. All three fail as assertions on both origin/main 9e6a50b2a and this tip, retained in duplicate-design-main and duplicate-design-tip. These are state evidence against the cited C function, not an oracle-green claim.

This is an L-sized registry design choice under the goal's design-first rule: C permits character/descriptor topologies that the one-name/one-body maps cannot represent, including different IDs retaining the same name. Sorting maps would invent a target order (R4); a lookup patch would leave the descriptor sweep and duplicate world extraction incomplete (R5b). Do not mark the parent complete from the four already supported modes.

Proposed design for approval: maintain ordered descriptor and character identity registries in C insertion order, with existing name maps as lookup views rather than identity ownership. Port descriptor selection/close, orphan-body fallback, extra-body extraction to room 1, and target adoption in C order. Preserve pointer-checked teardown and browser name holds. Add fixtures with multiple matching IDs, switched/menu/editor/playing descriptors, changed IDs sharing a name, descriptorless bodies, inventories and observers; verify both transports and admin name/ID readers. Complete the map/ID consumer audit in the same design, since character lookup, object locations, persistence and Go-only ownership currently share names.

Related boundary: Go RecordToPlayer restores objects before performDupeCheck, whereas C has not Crash_load'ed the disposable candidate. Adoption must discard only the loaded candidate's objects without touching the retained body's objects. Current location ownership uses player names, so a naive ExtractRentedObjects call can resolve to the old body and mark its crash flag. Include that owner-sensitive cleanup in the registry design rather than adding another incomplete name-only patch.
