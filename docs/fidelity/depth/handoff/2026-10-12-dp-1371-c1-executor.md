# DP-1371 C1 shared actor executor — bounded train handoff

The executor train is committed at `43cd428764db1731299586354be5a82c3a879f79` on
`codex/dp1371-c1-executor`. It adds a shared C-style actor command path and uses
it for force on an NPC in the supported sit/stand starter set. It does not
establish generic NPC command parity.

The production Lua `action(me, line)` path carries a `CharRef` into
`WorldScriptableAdapter.Command`, then `World.NPCCommand`, then the session
executor. Force calls the same executor with the actual `MobInstance`. The
legacy VNum `ExecuteMobCommand` API keeps its previous dedicated behavior; its
broader command set has not been migrated. Existing player command handlers
and dispatch are unchanged.

The executor offers native specials in C order: room, worn objects, carrying,
room mobiles, then room objects. An applicable native entry without an
actor-aware callback returns `Unsupported`, so a partially ported native
special cannot be silently skipped. NPC room, worn, carried, and mobile Lua
`oncmd` arms remain gated as C gates them; room-object `oncmd` still runs for
NPC actors and receives `CMD_NAME + rawArgs` exactly, including delimiter
whitespace (`src/interpreter.c:1414-1476`). A real owner-typed Lua `RunScript`
probe and an argument recorder cover that boundary.

The ordering views are backed by the C list producers: `char_to_room` prepends
to `world[room].people` (`src/handler.c:532-545`), `obj_to_char` prepends to
`ch->carrying` (`src/handler.c:559-574`), and `obj_to_room` prepends to room
contents (`src/handler.c:901-915`). Supported Go movement and inventory paths
now maintain those C orders; the test suite covers current insertion and
removal paths. This scope does not claim every legacy mutation path is
exhaustively proven.

`force-mob` now matches C for the safe `force trainee sit` and `stand` probes
at seeds 1, 2, 3, 5, and 8. The first seed-1 census at the pre-reconciliation
manifest correctly reported `STALE` because the old expected-divergence rows
still classified the now-matching scenario as divergent. The D3
`force.visible-npc-target` claim is upgraded to five-seed live proof. D5
`force.npc-command-interpreter` remains blocked: these two starter commands do
not prove arbitrary NPC command handling, unsupported specials, or the full
command/position/RNG matrix. Its old force-mob divergence mapping and pins are
removed because the scenario itself now matches.

The following gaps remain explicit: native specials without actor adapters,
unported command handlers, mounted NPC dismount behavior, room/all force, and
generic Lua action parity. C continues to define the target and interpreter
contract (`src/handler.c:1303-1325`, `src/act.wizard.c:1869-1880`,
`src/interpreter.c:883-980`).
