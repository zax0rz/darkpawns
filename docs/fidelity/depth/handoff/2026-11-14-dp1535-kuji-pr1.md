# DP-1535 combat skills: Kuji Kiri batch

## Scope

This stop-tier batch routes the nine aliases `rin`, `kyo`, `toh`, `kai`,
`jin`, `retsu`, `zai`, `zhen`, and `sha`, which all dispatch to C's
`do_kuji_kiri`. The remaining DP-1535 combat-skill rows remain for later batches.
The switched actor lane uses `game.CharacterKujiKiri`; ordinary player
commands keep the existing `cmdKujiKiri` path.

## C path and Go state

The command aliases and their C dispatch are recorded in
`docs/fidelity/dp1521-switched-mob-commands.tsv`. C reaches
`do_kuji_kiri` without an `IS_NPC(ch)` refusal (`src/new_cmds.c:1552-1739`).
At levels below immortal, a non-ninja mobile gets the class refusal. An
immortal-level mobile passes that gate; `check_kk_success` consumes
`number(1,101)` before reading `GET_SKILL` (`src/new_cmds.c:1501-1540`).
NPC prototypes use class zero (`src/db.c:1096`) and share the zero-initialized
`dummy_mob` skill record (`src/db.c:104,1281`; `src/utils.h:289,343`), so the
fresh mobile then gets the mastery refusal.

That shared skill state is mutable in C. `do_restore` sets every skill to 100
when a greater god restores an immortal-level target (`src/act.wizard.c:1599-1601`),
and Lua `set_skill` writes the shared mobile record (`src/scripts.c:1365-1380`).
Go now represents the shared default and overrides on `World`; mobile Kuji
reads that state, and mobile restore updates it. The Rin success witness proves
the restored value reaches the switched body. The handler has no `WAIT_STATE`
(`src/new_cmds.c:1552-1739`), so this batch does not introduce a wait.
