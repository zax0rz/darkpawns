## What changed

**1. The brag was computed and dropped.** `combat.BragMessage` delivers through
`cbBroadChat` → `callbacks.BroadChat` (pkg/combat/callbacks.go:252), and nothing
in `pkg/` or `cmd/` ever assigned it. It is now wired in
`WireCombatCallbacks` to `World.mobGlobalGossip`, the NPC-authored gossip sink
the port already had for quan_lo (pkg/game/comm_channel.go:239) — which is
`do_gen_comm(SCMD_GOSSIP)` for an NPC and therefore also writes review.

**2. The brag's gates now precede both draws.** `BragMessage` returns before
drawing when the killer is not `MOB_AGGR24`, when `can_speak(ch)` is false, or
when `ch == victim` (src/fight.c:1161-1172). A new `CanSpeak` callback carries
`can_speak` into the combat package. Case 5 is now
`IS_EVIL(ch) && !IS_EVIL(victim)` (:1195), and case 1's possessive is pinned
against the port's sex encoding. The brag itself moved into `attitudeLootMob`,
which is where C has it — after the loot, the junk and wear passes, and the
`(LOOT)` mudlog.

**3. Mob-on-mob kills loot and brag.** The call site is now one helper,
`attitudeLootAfterKill`, invoked from both victim branches at C's position after
the death handling (src/fight.c:1693-1697). The port had it only in its
player-victim branch.

**4. Every mobile speech sink goes through the real channel.**
`hunt_victim`'s says now use the mobile `do_say` (the room hears them), its
tells the mobile `do_tell` (gates + the player path's own `perform_tell`, which
adds C's `CCRED`/`CCNRM` sandwich and `GET_LAST_TELL`), and its gossip, auction
and shout one NPC-authored `do_gen_comm` that keeps the shout's zone and
position filter. Case 4's invented "they're bad" is C's
`"I hear %s thinks %s's bad."` with `HSSH`. The legacy VNum adapter's
`say`/`emote`/`gossip`/`tell`/`shout`/`auction` cases call the same helpers, and
the hand-built stubs are deleted.

**5. The specials speak through `act()` with C's text.** The undead knights' and
mickey's taunts used `roomMessage` with `me.GetName()` and had three "corrected"
typos; mickey's stand was a hand-built `"stands up!"`; the con-seller's tell now
assigns the reply target.

**Checked and left alone:** the Lua bridge's `Say`, `Emote`, `Tell` and
`Command` already route through `npcSay`, `npcEmote`, `npcTell` and `NPCCommand`
(pkg/game/world_bridge.go:335-360), so that path needed no change.

### Oracle vehicle for the brag itself: none is available inside this brief's boundaries

The brief asks for an oracle vehicle "where existing fixtures allow one, for
example a hunting mob with a player observer in another room". No existing
fixture reaches the brag's kill or a mobile's hunting state, and the reason is a
hard constraint rather than an inconvenience:

- **The hunt vehicle needs an attack.** `HUNTING(ch)` is set by `damage()`'s
  hunter arm when the mobile is hit (src/fight.c:1453-1455) or by Lua
  `set_hunt`. The harness has no fixture that sets a mobile's hunting target
  (`internal/oraclediff/scenario.go` exposes `set-mob-flag`, `set-mob-aff`,
  `spawn-mob`, `force-load`, `replace-room-exits` and `quiet-mobs` only), so a
  scenario must first attack the hunter — the attack path GLM is changing for
  DP-1438 (`StartCombat` call sites, `attackHuntingPrey`), which this brief says
  to stay away from. Adding a harness fixture is explicitly out of bounds (stop
  tier: "no changes to … the census harness").
- **The brag vehicle needs a kill, and its one candidate room is peaceful.** The
  only AGGR24 fixture is `mobact-aggr24-invisible-npc-target`, which
  deliberately prevents a target from being selected, and its room (8162) is
  `ROOM_PEACEFUL` — where C's first swing is refused before any enrolment while
  the port's `StartCombat` enrols first. That divergence is filed separately as
  `mobact.peaceful-first-hit-enrolment`; building a kill vehicle here would
  import it into this diff.
- **R3 is therefore proven with seeded draws**, which the brief allows
  ("Otherwise, use seeded unit draws"): `bragRoller` scripts the two brag draws
  by their bounds and records every draw, so `TestMobKillBragGates` proves each
  gate burns zero draws and `TestMobOnMobKillLootsAndBrags` proves the
  mob-victim path burns `number(0,20)` then `number(1,12)` in C's order.

Proposed follow-up vehicle, once DP-1438 lands: a scenario in a non-peaceful
room that spawns a stock `MOB_HUNTER` mobile (172 exist; vnum 7 "a lunatic" is
level 12 and intelligent), has the actor attack it, walks two rooms away and
pulses — the hunter then moves without arriving and taunts through
gossip/auction/tell, which is exactly the class this train fixed.

## Same-class residuals (reported, not fixed)

- **`GET_WIS`/`GET_INT` gates.** C's `do_say` (src/act.comm.c:767-771) and
  `do_gen_comm` (:1223) refuse a character with WIS or INT 0, and `do_echo`'s
  emote arm refuses on `PLR_NOSHOUT || GET_INT == 0` (src/act.wizard.c:139-143).
  The mobile helpers do not carry those gates. Adding them changes no stock
  behaviour — **0 of the 1115 mobiles in `lib/world/mob` has INT or WIS 0** —
  but it silences the synthetic mobiles three existing tests build without
  stats, so it wants its own train with fixture updates rather than a silent
  edit here.
- **The race-hate act** in `mobile_activity` (src/mobact.c:252-253) still goes
  out through the port's hand-rolled `RoomEcho`; that is DP-1435's residual, not
  this train's.
- **`conSellerTell`'s rendering** keeps a bespoke PERS because the shared act
  engine takes no room argument and C's `CAN_SEE` includes `LIGHT_OK` for that
  deliberately dark shop. Only the reply target was added here.
