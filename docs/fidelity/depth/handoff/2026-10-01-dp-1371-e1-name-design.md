# DP-1371 E1: name validation design and policy decision

Base: fresh origin/main `5a060e692`, after #1744. This is a design-first stop,
not a proof-only completion. No manifest status or production behavior changes.

## C path and confirmed gap

`src/interpreter.c:1743-1759` closes on empty input, then applies `_parse_name`,
length 2–20, `Valid_Name`, fill_word and reserved_word before looking up a saved
record. `_parse_name` (`1505-1520`) skips leading whitespace and rejects every
nonalphabetic character thereafter, including trailing spaces. The limit is
`src/structs.h:647`. The exact fill/reserved lists are
`src/interpreter.c:853-876`. `src/ban.c:257-291` checks descriptors before the
invalid substring list: a matching CON_PLAYING descriptor permits login, while
a matching creation descriptor rejects it. This must not become an unconditional
online-name rejection (R5e).

Go's live terminalName and handleLogin both call
`validation.IsValidPlayerName`, which permits digits/underscores, allows up to
32 characters and uses a different reserved list. The later game helper clamps
unknown names to 20 but does not provide the C character/fill/reserved checks.
handleLogin performs the shared validation before saved lookup; terminalName
also validates before forwarding. TerminalLine and get_name creation input
trim both ends; initial JSON name input does not. The class search found two
production callers of IsValidPlayerName, both in this entry path.

A temporary test drove real handleLogin on unchanged main with Fighter123,
a_b, the and self. All four assertion failures show confirm_name instead of
C's rejection/get_name state. Source and complete failure log are retained at
`~/Archives/darkpawns/oracle-runs/2026-10-01/dp-1371-p4-entry-name-design/`.
The test is not a passing fidelity proof and no oracle-green claim is made.

## Proposed implementation

1. Add one C name parser/gate at the session entry boundary. Route initial
   telnet, initial JSON login and nanny get_name retries through it, before
   lookup. Preserve leading-only space skipping, alphabetic bytes, 2–20 length,
   exact case-insensitive fill/reserved rejection, and C prompt/close behavior.
   Transport code must pass name bytes intact to that gate; leave command and
   password handling outside this change.
2. Audit descriptor-aware duplicate checks separately from durable folded
   lookup. Preserve playable reconnects and reject names held in creation.
   Do not use the existing blanket HasActiveCharacter rejection as C evidence.
3. Keep invalid-substring data authoritative and prove matched/nonmatched,
   casefolded input. Do not add shipped fixture names or change save formats.
4. Prove initial and retry paths, empty/all-space/leading/trailing spaces,
   lengths 1/2/20/21, digits/underscore/punctuation, every C fill/reserved word,
   banned substring, mixed-case acceptance and repeat prompt. Use real SQLite
   for saved-name validation order and real telnet/WebSocket transport tests.
   Retain explicit browser-rendering ownership in entry.browser-name-routing.
5. Add paired live creation scenarios and inspect C rejection/confirmation
   blocks; make each gate/message/state proof fail under a targeted mutation.
   Run full census and claims census because implementation touches shared
   entry/session paths. Stop at the implementation PR.

## Decision required: Go-only reserved names

The existing case-insensitive list is admin, system, root, server, null,
undefined, gm, moderator, god, implementor, imp, staff, dev, bot, agent and
zax0rz. C's fill/reserved lists do not specify this policy. zax0rz is already
rejected by C's character rule; the other entries need an explicit choice.
Git blame traces the list to commits `1fb8cd8388` and `d5e631f075`; these are
implementation history, not a cited approval to classify a divergence.
A search of docs/briefs, docs/fidelity and security documents did not find a
specific approval for this list.

Recommended: retain this exact security-name restriction as its own
`entry.security-reserved-names` divergent-approved row, with an approval issue
and focused fail-capable test. The C-parity row would explicitly exclude that
approved overlay. Alternative: remove the extra restriction for C fidelity.
Zach must choose and provide/authorize an approval citation before this row
can be classified, as required by the goal's Entry security decision.

The guest-prefix bypass is another existing Go entry surface
(session_login.go); it must be accounted for separately rather than silently
included in a C-parity claim. This design does not propose removing guest
login or approving its whole surface. Its current ownership/approval needs to
be resolved before an unrestricted name-validation completion claim.
