# DP-1371 D5 queued-close output design

Stop tier: descriptor output queues, idle descriptor retirement, both transports, and the live point-update driver. This is a design-first note under the Phase 4 goal; it changes no runtime code. The room-index correction is independently proven in #1769.

A fresh seed-1 run against the production source of merged main (`99fa0e648`) reproduces the terminal hour exactly:

- Go: `The suns slowly disappear in the west and south.` then `<CLOSE>`.

The vehicle removes only the inside-void fixture from the existing force-rent-close scenario. The baseline binary was built from #1768's tip; a production-source diff against the merge commit is empty. It uses the unchanged reference oracle. This is content divergence, not infrastructure failure. R1/R5e/R5g/R5h.

C's game-loop output pass precedes heartbeat (`src/comm.c:636-645,679`). The hourly block runs weather, affect_update, then point_update (`src/comm.c:825-828`); sunset queues outdoor output (`src/weather.c:65-71`, `src/comm.c:2352-2363`). check_idling closes its attached descriptor before rent and extraction (`src/limits.c:438-451`). close_socket closes the socket, releases its queues, saves the attached character and emits the room act and log, then removes/frees the descriptor (`src/comm.c:2092-2093,2130-2135,2145-2171`). The terminal weather never reaches the next output pass.

Go sends to channels consumed immediately by telnet writeLoop and WebSocket writePump. CloseSend preserves buffered channel entries; draining them later cannot retract a frame already consumed by a writer. Session extraction runs on the following pulse. Live point_update has a World ticker; only DP_CLOCK uses the hourly heartbeat callback. A seam-only change would leave the live race intact.

## Proposed implementation

Use a bounded output transaction around a heartbeat turn, with synchronous descriptor close at the existing idle-close site. This ports C's queue/close boundary without replacing the entire server event loop.

1. Make the hourly heartbeat the sole point-update driver in live and DP_CLOCK modes. Remove the standalone point-update startup in NewWorld and its production ticker path; preserve 630-pulse cadence, callback order, and direct PointUpdate calls used by unit tests. Do not move combat or unrelated event drivers. Verify World construction has no remaining hidden point-update startup and server startup wires exactly one driver.
2. Add begin/end hooks around heartbeat work, shared by the live runner and PumpPulses. Live staging surrounds one heartbeat turn, after its initial input drain. PumpPulses stages the entire requested burst and commits once after its last heartbeat, matching C's deferred seam: C does not flush between pumped pulses. Committing after each hour would leak earlier queued weather if a later hour in the same burst closes the actor. Keep ordinary command scheduling unchanged; document and test how the existing per-pulse input drain interacts with an active pumped transaction. Use a deferred end so callback panic handling cannot leave the output batch active. Do not hold a mutex while invoking world callbacks. Commit surviving descriptors' frames in enqueue order, before their trailing prompt. End retains a committing state while draining: concurrent enqueues append behind staged frames until the queue is empty and the state atomically returns to ordinary delivery. A detached list followed by immediately enabled direct sends would allow newer output to overtake it and is forbidden. Async prompt requests made inside the turn are deferred to its final sweep, including the prompt sweep currently called by transport disconnect. Outside this interval, existing send behavior remains unchanged.
3. Route all session enqueue paths reached within that turn through one staging-aware guarded delivery helper. Stage immutable frames by Session identity, preserving per-session FIFO, existing bounded/drop policy, structured envelopes and GMCP ordering. Audit every direct channel send, including manager message sinks/broadcasts, prompts, raw events, observation, agent vars, and GMCP; none may bypass staging during the turn. New or concurrently closing sessions must use the same batch state, rather than relying on a snapshot of sessions taken at begin.
4. Add a world-to-session idle-close callback at CheckIdling's existing close_socket position: after the translated transfer, before rent and extraction. The manager resolves the attached descriptor, marks immediate discard, cancels its staged frames, and closes its transport synchronously. Factor the existing close/save/room-act/log operations so they execute once and in C order; do not call HandleTransportDisconnect alongside the current world act/log and thereby duplicate them. Keep later unregister, rent-object cleanup and extraction at their existing ownership boundaries. An already detached or descriptor-less original body does not acquire or close another descriptor. Treat immediate idle close as distinct from orderly quit during a burst: C queues the goodbye and defers extraction to its subsequent pulse, so legal-quit output must retain its existing flush behavior. Preserve active-switch attached/original selection and both reconnect identities.
5. Discard output without snoop forwarding when the descriptor closes before commit. Forward surviving staged text to the snooper at the flush boundary, preserving C delimiters and avoiding recursive staging/forwarding. Commit output bookkeeping only for delivered player text so discarded frames cannot create a later prompt. Retain entry errors and legal-quit goodbye flushing on their ordinary paths; immediate idle close must not become the generic CloseSend policy. If an orderly CloseSend occurs with accepted staged frames, represent it as a FIFO close barrier: stop accepting new frames, commit previously accepted output, then perform channel close. Distinguish this pending orderly close from an already closed channel and from immediate discard; otherwise the final closed-state guard would erase the goodbye. Do not change transport cleanup until boundary tests prove that staged close barriers preserve the existing goodbye drain.

The transaction stages every frame emitted during the heartbeat turn or pumped burst, rather than postponing only weather. Otherwise hunger/affect messages could overtake weather and violate R1/R3b. It also avoids predicting idle outcomes from timer/level or changing the void room to hide the failure.

## Lock plan

The output batch mutex protects only batch state and immutable frame lists. It never encloses world callbacks, persistence, socket writes, lifecycle transitions, or calls that take manager/world/player locks. Enqueue paths may enter it under existing manager locks, but no batch-locked path acquires those locks in return.

Begin/end detach batch state under that mutex and release it before delivery. The existing per-session sendMu guards the channel-close/send decision. Do not hold the batch mutex and sendMu together. Immediate idle close cancels staged output under the batch mutex, releases it, then uses sendMu and the transport close path. Final delivery rechecks the immediate-discard/closed state under sendMu, so a concurrent close cannot resurrect a detached batch.

The idle descriptor callback takes playerLifecycleMu only for actual idle-close work, then uses the existing manager-locked attached-body resolution and close/switch operations. CheckIdling must enter the callback with world/player locks released. The callback releases lifecycle ownership before returning to rent/extraction; neither the output transaction nor ordinary movement takes that lock. The implementation PR must list actual lock acquisitions for each new path, including all active-switch branches, and reconcile them with existing lifecycle ordering. No mutex may be held while waiting for a writer to acknowledge a frame.

## Failing-first proofs and release gate

- Preserve the original weather-active 31-hour vehicle, with the terminal hour in its own compared block and real outdoor visibility. Prove C's sunset block and `<CLOSE>` on the actor; indoor suppression is not evidence. Claim seeds 1,2,3,5,8 only after each passes.
- Add a burst variant with several hours in one pump: if the actor closes before the next output pass, all earlier unflushed output in that burst is discarded too. A per-hour commit mutation must fail.
- Unit test stages actual weather before a forced idle close, with a competing writer ready to consume; no terminal frame reaches either transport. Revert staging/close ordering and fail an output assertion, not a timeout.
- Surviving outdoor descriptor receives weather followed by point-update text, then its prompt; use distinct messages to prove order. Reverting to weather-only deferral must fail.
- Independent telnet and WebSocket boundary tests, with actor, room listener and snooper. Closed actor's staged output must not reach the snooper; the room listener receives exactly one lost-link act and prompt.
- Ordinary sends, input markers, raw events, GMCP, entry refusal, legal quit, linkdead retention and idle rent/relogin remain covered. Exercise bounded/full queues and a concurrent close at commit with assertions and `-race`.
- Active-switch tests cover an idling original without an attached descriptor, an idling borrowed body with an attached descriptor, both saved identities, and no duplicated close/save/act. Existing switch reconnect and extraction tests stay green.
- Engine tests prove the same hourly callback order and exactly one point update in live and pumped modes; direct World unit calls remain usable. Mutate the driver gate/startup to show that the driver-count proof fails.

One commit per case/prerequisite, normal gates, then one combined census at the implementation tip. Any changed scenario must be explained with paired C output at the exact pulse; no repins, dropped seeds or new convenience divergences. This implementation remains stop tier and stops after opening its PR.

## Scope boundary

Approval would authorize the proposed shared heartbeat queue boundary and driver unification, not a general session registry redesign or a global transport rewrite. If implementation requires changing non-hourly command scheduling, holding lifecycle ownership across a heartbeat, or expanding another retained identity/ownership frontier, revise the design and stop. Browser name routing, storedPlayer/PlayerStoreEdit loaded inventory, legal-quit ownership and the separate teleport combat gap remain retained.
