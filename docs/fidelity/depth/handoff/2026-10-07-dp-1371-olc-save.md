## Lock acquisitions and delivery audit

- `SaveList.Mark/Remove/Dirty/List/Ordered`: SaveList mutex only, released before callers proceed. No world/zone/output callback inside the SaveList lock.
- Save-info and head selection: brief SaveList mutex via `Ordered`, release, then ordinary session delivery. Acknowledgements are sent without a save-list, zone-save, world, manager or lifecycle lock held by this command.
- `saveOLCEntry`: `ZoneSaveLock` briefly acquires/releases the lock-map mutex; then the one zone mutex. Under the zone mutex: brief SaveList `Dirty`; brief world RLock for `SnapshotZone`; the chosen existing writer's world snapshot(s), released before filesystem operations; brief SaveList mutex to remove the successfully written entry. The zone mutex is released on all returns. No nested acquisition of the zone mutex: use the existing `*ZoneLocked` functions.
- REDIT snapshots rooms; OEDIT/MEDIT/SEDIT obtain the parsed path and snapshot objects/mobs/shops; ZEDIT snapshots its zone. All world RLocks are scoped inside those methods. Existing OLC commits acquire the same zone mutex, then commit under world lock, release world, mark under SaveList mutex. The new command takes the same order, not the reverse.
- Final success producer: no save/list/world/zone lock held. `GetName` reads the acting PC, then MudLog uses its existing log/provider locks, snapshots descriptor state under manager RLock, reads player state and delivers through the existing sink. Error producer: writer already returned/unlocked; `GetParsedWorld` briefly takes/releases world RLock where needed, classifier stats the parent, then MudLog under the same zero-caller-lock invariant. Log-time tests require `zoneSaveLock(30).TryLock()` to succeed at both producers and inspect remaining markers.
- Existing session text delivery may stage under heartbeat output locks, inspect snooping under `snoopMu`, and enqueue under `sendMu` RLock; none is nested beneath a new save/list/world/zone lock. No player lifecycle lock added.
- Admin `SaveOLCZone` unchanged: initial world snapshot and registry snapshot are released before zone lock; then its five existing locked writers, with the world/SaveList sequence above. Admin room/entity commits keep their existing draft/claim and zone-lock ordering. This train adds no admin MudLog path or authorization change.
