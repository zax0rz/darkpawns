## Other readers and lock acquisitions

The producer belongs to the descriptor-issued handler, not the shared file
writer. Web OLC, admin saves and internal writer tests use existing save APIs
without acquiring a C do_olc player-facing producer. No serializer, dirty
marker, ownership registry, frontend, file format or persistence policy changes.
Interactive in-memory commits, saveall and failure diagnostics remain separate
producer cases; this bounded disk-save train does not certify them.

All five handlers finish holder/authorization/world snapshots before logging;
no edit, manager, world or lifecycle lock is held at the producer. The actor
send returns before MudLog. The existing save then takes the per-zone save
mutex and world snapshot locks, releases them and performs existing atomic
file writes. That ordering is unchanged. Shutdown logs after its actor send,
before manager RLock snapshots the targets; the lock releases before target
Act or ExecSave. No new lifecycle lock or registry is introduced.

MudLog finishes the file-writer lock before the provider snapshot, releases
manager RLock before callbacks, and uses the existing player/world sink,
heartbeat, switch, snoop and transport delivery. No new held-lock chain.
Admin `pkg/admin/olc_save.go` calls Manager.SaveOLCZone, which checks
claims, then holds ZoneSaveLock across the five Locked writers. Those paths
gain neither a log call nor a new lock acquisition.
