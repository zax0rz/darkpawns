## Delete and open proof boundaries

killEditorFile uses unix.Access(R_OK), C's real-uid check, and skips removal on
**every** access failure. It follows symlinks: absent, unreadable and dangling
links all return success and stay untouched where present. A readable file in
a non-writable parent passes access but fails removal and emits the error.
Non-root tests are required for permission claims; root runs skip those proofs.
No mode-bit approximation and no attempt to read file contents as an access test.

The disposable C script boots the unchanged reference from a copied library and
exercises real luaedit clear/save commands for readable, absent, unreadable,
dangling, delete-failure and non-directory-parent cases. It also saves root and
subdirectory Lua files and tedit help, asserting file bytes and exact process-log
payloads. Raw actor transcripts and process log are retained. This is a C
operation/command witness plus Go unit state/recipient proofs, not a new
oracle-green corpus claim. No reference binary replacement or instrumentation.

For AtomicWrite errors, only an inspected missing/non-directory parent is mapped.
Linux os.OpenRoot's direct non-directory-root refusal has a non-errno cause;
the extra guard requires PathError.Op=open and PathError.Path equal to that
actual parent, then verifies it is not a directory. Other shared missing-parent
errno cases use the prior bounded classifier. Permission/resource/leaf-stat,
write/sync/close/chmod/rename failures acquire no guessed fopen diagnostic.
Broader fopen parity stays unproven; the aggregate stays blocked.

## Locks

All four producers run in finishTextEditLocked with **textEditMu → liveTextEditMu**
held. AtomicWrite's **writeMu** has already been released on return. There is no
world, player, lifecycle, zone-save or script-engine lock held at these calls.
Success name lookup briefly takes **manager.mu.RLock → body/player getter lock**,
then releases both before MudLog. Descriptor input/drain owns no manager/world
lock when entering the editor; OLC callbacks return before these producers.

MudLog's file/provider locks release before EachSession snapshots manager.mu;
recipient flags/levels/colors take short player locks. Player.SendMessage reads
world.mu.RLock to obtain MessageSink and releases it before descriptor lookup,
heartbeat staging, snoop and send locks. Those delivery paths do not take either
editor mutex. SendPrompt/editorPromptState takes textEditMu, but MudLog calls
SendMessage, not prompt rendering. This avoids a recursive editor acquisition.
The provider's active-switch lookup remains manager-locked and does not acquire
editor locks. No recursive world read lock is held by a producer.

Cache/web notifications keep liveTextEditMu ownership; no MudLog in shared web
writers. Disconnect cancellation serializes with save using textEditMu then
liveTextEditMu. TestFileEditorSaveCleanupRace covers the two possible serialized
outcomes; existing TestWebTeditSaveDoesNotRaceLiveReaders covers web/cache readers.
The existing forgetScriptFailures engine-lock path is untouched and runs after
ack; the new delivery calls do not acquire that engine lock.
