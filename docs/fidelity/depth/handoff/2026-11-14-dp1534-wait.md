# DP-1534: switched-body wait state

## Scope and C call path

`WAIT_STATE(ch, cycle)` writes `ch->wait` (`src/utils.h:462-464`). The descriptor
loop decrements `d->character->wait` and reads the next input only when that
wait reaches zero (`src/comm.c:597-612`). After a mob switch,
`d->character` is the mobile (`src/act.wizard.c:1196-1200`). The Go dispatcher
already resolves that body in `characterCommandContextForSession`; the input
gate and pulse drain now use the same body selection. The descriptor owner
retains its own wait while the mobile is attached.

`CharacterHit` now sets the mobile body's 22-pulse wait after the valid `hit`
branch calls the combat engine, matching `src/act.offensive.c:101-129`.
`CharacterDrop` already sets the mobile wait for a successful coin drop
(`pkg/game/item_transfer_actor.go:349`, C `src/act.item.c:443`); the descriptor
queue now drains that body wait as well. The retained red scenario is restored
to the corpus at `cmd/dp-oracle-diff/scenarios/switched-body-combat-lane-wait-depth.txt`.
The added `...-body-context-depth.txt` witness keeps the owner in room 8105
while the switched mobile moves to 8162 with separate inventory and equipment.

## R5c audit of all C wait sites

This inventory was made from every `WAIT_STATE(` in the six source files below:
58 calls total, 50 target `ch`, and 8 target a victim variable. Victim waits are
included because a command by another character can set the wait on a switched
body. The command layer applies combat skill target waits to either `Player` or
`MobInstance` (`pkg/command/skill_commands.go:1824-1835`); ambush does the same
for its target (`pkg/game/ambush.go:101-102`). The manager now decrements the
active descriptor body's wait in either case.
