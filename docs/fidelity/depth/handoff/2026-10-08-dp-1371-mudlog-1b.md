## Classified, not implemented (for Zach)

**`scripts.c:1765` (unassigned script) → `blocked-reachability`.** C reaches
`!*script_name` because its callers gate on the trigger *flag* only; the port
gates on the name first, so its unassigned arm is unreachable:
`MobInstance.HasScript` returns false when `m.Proto().ScriptName == ""`
(`pkg/game/scripts.go:25-28`) and is the only gate on the mob path, and the
object path does the same in `objHasScriptTrigger`
(`pkg/game/room_obj_scripts.go:36-39`). C's payload for the remaining owner
types is itself undefined (`GET_NAME(me)` with `me` NULL for an object onpulse).
Making it reachable means relaxing `HasScript` to C's flag-only test, which
changes what every caller does — a routing decision, not a mudlog addition.

**`comm.c:784` (object weight) → `blocked-design`.** The port *can* hold an
object whose weight differs from its prototype: by design, via
`ObjectInstance.WeightOverride` and `SetWeight` (`pkg/game/object.go:38-45,
139-146`), written by the drink/fountain/consumable paths
(`pkg/game/item_consumable.go:106,347,429-430`). C's arm treats exactly that
state as corruption: it logs `SYSERR: Object '%s' weight incorrect, location
'%s'` and then repairs `GET_OBJ_WEIGHT(obj)` from the prototype
(`src/comm.c:783-785`). Porting the pair would therefore log a SYSERR on valid
states on every pulse and clobber the override, so it is a design decision
(what Go's invariant should be), not a producer to add. Not implemented.

## De-duplication vs #1854 (`scripts.c:1251`) — done

#1854 covered `fight.c` death-credit and death-message producers. The Lua
binding's own diagnostic is separate: `WorldScriptableAdapter.RawKill` logged
the same facts to `slog.Info("lua raw_kill", ...)` where C logs
`%s killed by %s at %s.` / `%s killed at %s.` at BRF/LVL_IMMORT/file FALSE
(`src/scripts.c:1246-1252`). No overlap; it is now a producer replacement, and a
killer ref that does not resolve falls back to C's no-killer line.

## Status

Every 1b scope item is landed or classified. Outstanding: this PR's combined
census, which waits for #1858 to merge and the rebase onto `origin/main`.

Two findings deliberately **not** fixed, recorded rather than folded in:

1. **Valid-path nil/0 (R1/R2, for Zach).** On the *valid* path `lua_canget`
   pushes `0` where C pushes nil (`pkg/scripting/engine.go`, the
   `CanCarryObject` tail). Lua treats `0` as true, so a script's
   `if canget(obj) then` takes the wrong branch when the object cannot be taken.
   The ruling scoped Q4 to the bad-argument arms, so this is reported, not
   changed.
2. **`lua_item_check`'s no-shop arm is now reachable by a new query.** The
   keeper lookup is a Go-only addition to make C's condition expressible; it
   changes no existing signature and no interface, but it is new surface and is
   called out here for review.
