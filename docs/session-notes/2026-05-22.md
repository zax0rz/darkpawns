# Session 60 — 2026-05-22 (P1 Daemon Core Complete + WebSocket Fix)

## WebSocket Integration Bug — Fixed (75786a3)

**Root cause:** `completeCharCreation()` was missing the agent initialization handshake (vars, memory_bootstrap, memory_summary) that `handleLogin()` sends for returning players. Agent harnesses wait for these messages before transitioning to active state, so new characters never received command responses.

**Fix:** Added 3 lines to `char_creation.go` after `sendWelcome(token)`:
```go
if s.isAgent {
    s.sendFullVarDump()
    s.SendMemoryBootstrap()
    s.SendMemorySummary()
}
```

**Secondary fixes:**
- `flushDirtyVars` and `sendFullVarDump` now log warnings when their non-blocking sends drop messages (previously silent)
- `sendText` already had logging — confirmed it wasn't the culprit

**Found by:** Claude Code (Sonnet 4.6) via The Architect's manual diagnosis session. My own theory (channel filling up with 6+ messages) was wrong — `completeCharCreation` only queues 2 messages (state + MOTD), far from the 256-buffer limit.

**Lesson:** The agent harness protocol has implicit initialization requirements. Any code path that creates an agent session must send the full init handshake.

# Session 61 — 2026-05-22 (E2E Test + Docker Overhaul)

## E2E Test — Proven Working (249a3df)

**File:** `pkg/session/websocket_e2e_test.go` (188 lines)
**Test:** `TestWebSocket_NewCharThenLook`
**Flow:** login → 6 char_create stages → state → look command
**Result:** PASS in 0.08s

**Key insight from Claude Code:** My test clients were receiving zero messages because they were discarding `char_create` prompts looking for `state` that would never arrive. Without completing char creation, `sendWelcome()` was never called. The server was waiting for `char_input` that never came, the 60-second timeout killed the connection, and the client got nothing.

**Secondary finding:** `net.IP.IsPrivate()` returns false for 127.0.0.1 (loopback is RFC 5735, not RFC 1918). Test must set `ENVIRONMENT=development` to pass the loopback origin check.

## Docker Deploy Overhaul

**Before:** `docker build --no-cache` (3+ minutes, caching issues, layer invalidation failures)
**After:** Binary mount from host (10 seconds: build → scp → restart)

The Docker image is now `alpine:3.20` — a static base that never changes. The server binary lives on the host, mounted into the container. Deploy is just copying a file.

**Why this matters:** Eliminates the entire Docker build pipeline for server changes. No more `COPY . .` caching, no more layer invalidation, no more rebuilding images for a 3-line fix.
