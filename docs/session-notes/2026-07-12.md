### Oracle Differential Harness — PR #243 Landed
The tier-1 differential-test harness was built by Codex and merged to main. It drives both the C oracle and Go port with the same scripted input via telnet, normalizes transcripts, diffs them, and produces a divergence report.

**First run surfaced three real divergences:**

1. **Different starting room** — C drops new characters in "Temple Infirmary"; Go lands them "At the Temple Altar [8004]". Real start-location mismatch (related to DP-1077).
2. **Go leaks room vnum** — `[8004]` visible in room name line. In Diku/Circle, vnums are immortal/holylight-only; mortals shouldn't see them.
3. **Go dumps item stat blocks on room look** — Keywords / Type / Weight / Damage: 1d6 where C just says "A shiny short sword is here." Room-look shouldn't expand item internals.

**Significance:** Three fidelity findings from one `look` scenario. The harness paid for itself on the first run. These are the kind of behavioral divergences static code reading is unlikely to catch.

### Reek + Oracle Discussion
The Architect asked how the oracle could help Reek's pipeline. Key insight: Reek transitions from static code reviewer to behavioral difference detector. The oracle provides concrete evidence (C output vs Go output) for every finding, collapsing false positives to near zero and enabling regression detection.

**Proposed pipeline:**
- Scenario files → Oracle harness (C + Go) → Normalizer → Diff → Reek triages surviving diffs
- Reek stops reading code for pattern-matching; Reek operates the behavioral comparison pipeline and makes judgment calls on divergences
- Coverage expands from ~20% of codebase per crawl to 100% of behavior matrix

### Oracle Pipeline Roadmap (4 phases)
1. **Tier 1 widening** — movement/sector costs, object & shop interactions, score/equipment display, room descriptions. High coverage, low effort, worker-friendly.
2. **Tier 2 — random.c port** — the keystone. Deterministic RNG parity enables combat/skills/spells testing.
3. **Tier 3 — combat/skills/spells** — crown-jewel subsystems get reference oracle testing.
4. **Regression detection** — run scenario suite before/after merges, catch new divergences.

## Decisions Made

- Both servers driven over telnet/TCP (not WebSocket) for apples-to-apples comparison
- Harness is CI-gated (`DP_ORACLE_BIN` env var) — skips cleanly when C oracle isn't present
- Under-normalize bias: false diffs are cheap human glances, over-normalized real bugs are invisible
- Triage the 3 findings first (verify against src/*.c) before widening scenarios
