### What Happened

The Architect asked me to deploy the Go server with Hugo support to frankendell. After deployment, he pointed BRENDA (using MiniMax M2.7) at the skill.md to try creating a character. This was the first time AI agents attempted to play Dark Pawns.

### Agents

- **The Machine / BRENDA69** (GLM-5-turbo via OpenClaw) — Completed character creation after guidance. Explored Kiroshi. First AI agent to walk into Dark Pawns. Created characters: Blenda, Machine, Machine2.

### Bugs Found and Fixed

1. **JWT_SECRET not set** — Token generation failing silently in Docker. Added to docker-compose.yml.
2. **DP-232: Wrong hometown labels** — Go port had "Kiroshi" as option K (room 18201) instead of Kir Drax'in (room 8004). C source (`class.c: hometown_menu`) had correct values. Fixed labels and room vnum mapping. Deployed.
3. **Stale port in skill.md** — Said `ws://localhost:7777/ws` but server listens on 4350. Fixed.
4. **Missing `state` message documentation** — skill.md didn't document that `state` message = creation complete. Added with full example flow.

### Architectural Finding: SEEP

Opus subagent analysis revealed the core issue is NOT timing (writePump async) but state-mismatch. Agents send wrong message types or reconnect before state updates arrive. The protocol is unforgiving when agents lose sync.

**Recommended fix:** State-Echo Error Protocol (SEEP) — when server sends error, re-send current expected prompt. ~80 lines. No new message types. Humans don't notice. Agents become self-healing.

Created DP-233 for implementation. Full analysis saved to `docs/reports/agent-architecture-analysis-2026-05-21.md`.

### Session Duration

~2.5 hours. Very intense. Multiple model attempts, debugging, deployment, architectural analysis.

### What I Learned

1. **Different models fail differently** — M2.7 can't write valid JSON, GLM-5-turbo completes creation but reconnects too fast. Same protocol, different failure modes.
2. **"wait for the response" doesn't work** — Agents can't be trusted to follow timing guidance. Need server-side solutions.
3. **The async-write diagnosis was wrong** — Opus analysis revealed the real issue is state-mismatch, not timing. readPump is sequential; server state is correct before next message is read.
4. **Port fidelity bugs surface when agents play** — The hometown labels were wrong for months. Humans never noticed because the web client handles it. Agents exposed it immediately.
5. **SEEP is the right fix** — Making the protocol more honest about its state for everyone, not just agents.
