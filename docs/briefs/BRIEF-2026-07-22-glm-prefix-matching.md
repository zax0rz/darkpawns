## The C truth — three laws (read interpreter.c:883-935 yourself first)

```c
for (length = strlen(arg), cmd = 0; *cmd_info[cmd].command != '\n'; cmd++)
  if (!strncmp(cmd_info[cmd].command, arg, length))
    if (GET_LEVEL(ch) >= cmd_info[cmd].minimum_level)
      break;
```

1. **Prefix, one direction.** The typed word must be a prefix of the table name
   (`mur` → `murder`). Typed-longer-than-entry never matches (`grinx` matches nothing).
2. **Table order wins, not alphabetical order.** First matching entry in `cmd_info[]`
   line order. This is why the `qui`/`shutdow` stub entries exist (they precede
   `quit`/`shutdown` and force exact typing — their messages are part of the surface).
   Socials (`do_action` entries) are interleaved in the same table: `gri` resolves by
   line number (`grin` :475 before `grimace` :476).
3. **Level filters DURING the scan.** A prefix-matching entry above the player's level
   is skipped and the scan continues — a mortal and an immortal typing the same prefix
   can resolve to DIFFERENT commands. Resolution is level-dependent, not just execution.

Post-resolution checks (position messages, FROZEN, "Sorry, that command hasn't been
implemented yet.") happen AFTER the scan — they are already ported/gated elsewhere; do
not move them into resolution.

## Implementation

1. **Emit table order as data.** Extend `cmd/dp-command-gates/main.go` (which already
   parses `src/interpreter.c`) to also emit an ordered resolution table —
   `pkg/session/command_order.tsv`: `seq  name  min_level`, one row per C table entry
   in source order, socials included, `qui`/`shutdow` stubs included. Golden-file
   pattern like `command_gates.tsv` (embedded, regenerated by the tool, drift-tested).
2. **Ordered resolver in front of the registry.** In the lookup path
   (`pkg/session/commands.go`): lowercase the typed word, scan the ordered table with
   the three laws above, resolve to the canonical name, then dispatch via the existing
   exact-match registry / socials path under that canonical name. Existing
   `command_gates.tsv` position/level gating still applies post-resolution — don't
   duplicate it.
3. **Go-only commands** (modern additions: `ignore`, `map`, `autoloot`, the
   `goOnlyCommands` set, player aliases as today): resolved by **exact match only**,
   consulted only when the C scan misses. They must never win by prefix or shadow C
   resolution order (R4 — abbreviations are C surface; Go-only names are not).
4. **Player alias expansion** stays where it is (before resolution). **Spec-proc
   interception** stays where it is (before resolution) — note: C calls `special()`
   with the *resolved* cmd, Go intercepts on raw strings; that architectural divergence
   is out of scope, do NOT "fix" it here.
5. **Tokenization from DP-1186 (`SplitCommandInput`) is upstream of this** — one-char
   punctuation commands arrive as one-char words and resolve exactly (they're in the
   C table too). Don't special-case them.
