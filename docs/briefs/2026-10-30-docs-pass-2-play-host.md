## Runtime measurement method

Built `cmd/server` from commit `04b4145a8b4cd954483b3e47ac64d468a0418098` with `go build -buildvcs=false`, then started that binary from the repository root with HTTP bound to `127.0.0.1:4373`, telnet disabled (`0`), an isolated temporary SQLite database, and the bundled world. The host reported Linux x86_64. Readiness was the local `/health` response. Wall time from process launch to health response was 0.42 seconds. `/proc/<pid>/status` RSS was sampled at readiness and +5, +10, and +15 seconds: 83,864 KiB, 87,972 KiB, 87,976 KiB, and 86,856 KiB. `du -sb` reported 5,298,335 bytes for `lib/world`, 393,851 for `web/public`, 40,238,208 for the built server, and 1,201,375 for `admin-ui` source. No built admin UI distribution exists in this checkout. This was one idle local startup without connected players; it does not establish a production minimum or load capacity.

The existing-machine provider-fee statement follows the operational scenario rather than a provider quote. The license is the controlling cost restriction: `LICENSE` §1(a) prohibits fees, donations, compensation, and reimbursement of hosting costs. The page links to the full license and gives no cloud-price example.
