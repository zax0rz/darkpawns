## CRITICAL: Packages With Zero Tests

### pkg/storage — 0.0%
**File:** pkg/storage/sqlite.go, pkg/storage/interface.go
**What:** 229 lines of SQLite-backed data persistence with zero test coverage.
**Why it matters:** Every database write path is untested. Corruption bugs, connection handling errors, migration failures — invisible until they hit prod.
**Suggested fix:** Add SQLite in-memory tests for each Storage interface method. Existing test pattern to follow: pkg/db/convert_test.go.

### pkg/secrets — 0.0%
**File:** pkg/secrets/manager.go (127 lines)
**What:** Secrets management — loading, storing, encrypting credentials.
**Why it matters:** Untested encryption/decryption paths are a security risk. A silent key-derivation regression could lock everyone out.
**Suggested fix:** Unit tests with known test vectors for encrypt/decrypt round-trips.

### pkg/agent — 0.0%
**File:** pkg/agent/memory_hooks.go (411 lines)
**What:** AI agent memory hooks — REM synthesis, narrative event conversion, kill/death/social interaction triggers.
**Why it matters:** The agent memory pipeline has 13 exported functions with zero coverage. If REM synthesis fires on nil state or the narrative event converter drops data, no test catches it.
**Suggested fix:** Mock the LLM client, test each hook with sample event data.

### pkg/audit — 0.0%
**File:** pkg/audit/logger.go (144 lines)
**What:** Audit logging — security-relevant event recording.
**Why it matters:** If the audit trail is broken, nobody knows. Not until it matters.
**Suggested fix:** Test log writing, rotation, and query paths.

### pkg/common — 0.0%
**File:** pkg/common/random.go, shop.go, common.go, command_interfaces.go (156 lines)
**What:** Shared utilities including `Number()` random roll function.
**Why it matters:** The random number generator is the foundation of every dice roll in the game. If it's wrong, everything derived from it is wrong.
**Suggested fix:** Statistical distribution tests for random. Verify shop formula outputs.

## HIGH: Core Game Packages With Severe Gaps

### pkg/game — 14.7% (1251 of 1661 untested)
**What:** Core game logic — movement, combat actions, skills, items, clans, houses, communication, player state.
**Key zero-coverage files:**
- `act.go` — message routing, `Act()`, `SendToRoom()`, `SendToChar()` — all 0%
- `act_comm.go` — language substitution, argument parsing, player lookup — all 0%
- `clan_*.go` — clan commands, membership, economy, banking, settings — all 0%
- `house_*.go` — house system (rent, boot, control, player, save) — all 0%
- `item_door.go`, `item_consumable.go`, `item_transfer.go` — 0%
- `limits_*.go` — exp, gain, condition updates — mostly 0%
- `player_social.go`, `player_stats.go`, `player_identity.go` — mostly 0%
- `skill_*.go` — skill combat, advanced, special, stealth — mostly 0%
- `world_movement.go`, `world_object.go`, `world_zone.go` — 0%
**Why it matters:** 75% of the game's runtime code is completely uncovered. Movement, item handling, skills, clans, houses — all untested. This is the biggest risk in the codebase.
**Analysis:** This package is 1661 functions large. It needs targeted tier-based testing. Start with movement (world_movement.go) and item transfer (item_transfer.go) — those touch every player every session.

### pkg/spells — 14.1% (62 of 86 untested)
**What:** Spell effect system — MagGroups, MagMasses, MagAreas, MagSummons, per-spell cast functions.
**Key zero-coverage functions:**
- `MagGroups`, `MagMasses`, `MagAreas`, `MagSummons`, `MagCreations`, `MagAlterObjs` — all 0%
- `ExecuteManualSpell` — 0%
- 20+ individual `cast*` functions — all 0%

**Analysis:** The golden test pattern from pkg/spells/saving_throws_golden_test.go should extend to each Mag* function. Individual cast functions need parameterized tests.

### pkg/command — 8.2% (89 of 97 untested)

### pkg/db — 8.1% (34 of 38 untested)

### pkg/optimization — 6.1% (100 of 107 untested)
**What:** Cache implementation, advanced worker pool, connection pool, websocket backpressure.
**Why it matters:** Concurrency primitives with zero coverage are ticking time bombs. Race conditions in `advanced_pool.go` (priority dispatcher, batch submission) or `cache.go` (TTL cleanup, concurrent access) will manifest as intermittent server failures.
**Analysis:** The only tested file is `object_pool_test.go`. Cache TTL behavior, pool resize, and websocket backpressure all need tests.

## Recommendations

1. **Target pkg/game first** — it's 51.6% of the codebase by function count. Focus on:
   - `world_movement.go` (movement is every player action)
   - `item_transfer.go` (item give/drop/get is every interaction)
   - `act.go` (message routing touches every system)
   - `player_combat.go` (pvp/e combat actions)

2. **Zero-coverage packages second** — pkg/storage, pkg/secrets, pkg/agent, pkg/audit, pkg/common. These are small enough (1-2 files each) that full coverage is achievable in a single session.

3. **Spell system third** — golden test pattern is established in pkg/spells/saving_throws_golden_test.go. Extend to Mag* functions.

4. **Command handlers** — admin_commands.go has security implications. Shop_commands.go has economic implications. Both are table-drivable.

5. **dp-agent CLI** — 13 functions, all uncovered. The agent CLI is the primary deployment tool.

## Trend Note

This is the first comprehensive coverage audit. No prior baseline to compare against. Overall coverage likely declined as new code outpaced test writing. The 72.1% zero-coverage rate across all functions is a problem — over 2 out of 3 functions have never been executed by a test.
