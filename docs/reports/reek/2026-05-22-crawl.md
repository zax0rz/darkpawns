## CRITICAL

- **CRIT-001: Client double-appended to shared slice causes data race, duplicate sends, and dangling references**
  - File: `benchmarks/websocket_benchmark_test.go:286`
  - What: The HTTP handler appends WebSocket connections to `clients` under lock; then the benchmark setup loop appends the same connections a second time without any lock.
  - Why it matters: Every message gets sent twice to each client, `conn.Close()` is called twice per connection, and the second duplicate becomes a dangling pointer to a half-closed connection.
  - Source: staticcheck (clawpatch confirmed — fnd_sig-feat-cli-command-eeeedf30f0-_d82ecab266)
  - Suggested fix: Remove the append on line 286; let the HTTP handler be the sole registrar.
