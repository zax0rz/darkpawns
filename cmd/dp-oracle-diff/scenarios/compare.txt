# compare (do_compare, src/new_cmds.c:1952) had two fidelity bugs the oracle
# surfaced: the Go wrapper invented a CanUseSkill gate (C uses APPRAISE only
# for the success prob, never to gate), and Go's DoCompare was a stub
# ("You don't have that item." / "X vs Y: comparing..."). Both are fixed to
# C's verbatim flow. The fixture supplies a second weapon and same-slot armor
# so the RNG comparison paths are live, not merely transcribed. The appended
# fixed-stat pairs straddle the five L1 report thresholds. A level-82
# appraiser keeps C's 1..101 success roll above every possible draw, so these
# five exact literals do not depend on the +/-3 failure noise.
#
# The fixture supplies the same carried object classes a fresh Warrior starts
# with, plus unambiguous fixed-stat weapons. Probes:
# - compare            → empty arg → "Looks like you don't have those objects.."
# - compare short short→ same object → "They're the same thing!"
# - compare short tunic→ weapon vs armor (type mismatch) → "You can't compare those things!"
# - compare short bokken→ weapon comparison result and C random-draw path
# - fixed weapon pairs→ each of C's five comparison-result thresholds
# - compare breast chain→ same-slot armor comparison result and C random-draw path
# - compare breast helmet→ different-slot armor gate
# - compare bag box→ same-type non-comparable-item gate
