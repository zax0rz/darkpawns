# Harness parity: server restart / crash recovery (docs/fidelity/HARNESS_PARITY.md).
#
# Mobile runtime state does not survive a restart: the mobile comes back with its
# prototype's hit points, in its reset room.
#
# C evidence: reset_zone() re-reads mobiles with the 'M' command (src/db.c:2107)
# through read_mobile(), which builds the instance from the prototype, and no
# shutdown path writes a mobile's hit points (src/comm.c:288-293). The Go port
# used to persist vnum/id/room_vnum/current_hp/max_hp per mobile in
# data/world_state.json (RULEBOOK R4).
#
# `set horse hit 1` wounds the spawned horse (do_set, src/act.wizard.c:2550:
# {"hit", LVL_GRGOD, BOTH, NUMBER}); do_consider's hit-difference clause is
# dice-free (src/act.informative.c:2380) and its target clause is not, so the
# blocks also consume C's damage draws — the restart claim is the physical-shape
# clause, and a draw-order divergence surfaces here as a real finding (R3).

# The actor returns to the immortal start room (1204) before quitting so the
# login room stays out of this vehicle's diff: C records no load room above
# LVL_IMMORT (src/act.other.c do_quit) and falls back to r_immort_start_room
# (src/interpreter.c:2195-2199). That quit-room rule is ported and proven by
# restart-login-room-immort (DP-1310); quitting elsewhere here would only
# re-prove it.
