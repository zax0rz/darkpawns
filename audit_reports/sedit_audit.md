# Port Fidelity Audit: Module 47 (`sedit.c`)

This audit examines the port fidelity between the legacy C source file `src/sedit.c` and its Go counterparts in `pkg/`.

---

## 1. Architectural Mapping & Discrepancies

### C Source File
- **File**: `src/sedit.c` (1,179 lines)
- **Functions & Features**:
  - **OasisOLC (On-line Creation) Shop Editor**: Implements the interactive Telnet menus (`sedit_disp_menu`, `sedit_parse`) that allow builders or administrators to configure shop parameters dynamically on the live server.
  - **Live Configuration**: Setup new shops (`sedit_setup_new`), modify products lists, business opening/closing hours, buy/sell profit markups, custom keepers' denial/success messages, blocked target races/flags (`with_who` constraints), and save results back to memory (`sedit_save_internally`) or write to disk `.shp` files (`sedit_save_to_disk`).
  - **Memory Allocation and Indexing**: Manually instantiates and copies integer arrays (`copy_list`) and shop structures to live server tables, shifting and updating indexes in-memory.

### Go Port Files
- **OMITTED (OLC System)**:
  - There is **no interactive Go shop editor**. The OasisOLC Telnet sub-menus have been completely bypassed.
- **Static Configurations**:
  - Shop loading in Dark Pawns is managed entirely **offline** using declarative CircleMUD-style `.shp` configuration files (under `lib/world/shp/`) parsed at boot time into runtime shop managers.

---

## 2. Validation of Saved/Parsed Fields

The loader system achieves complete compatibility with the formatting generated by C's `sedit_save_to_disk` (`src/sedit.c#L469-L551`):

1. **Product Lists and Multipliers**:
   - **C Save Routine**: Writes product VNums, terminated by `-1`, followed by floating-point profit rates `BuyProfit` and `SellProfit`.
   - **Go Parser**: Correctly reads product arrays and markup percentages, mapping Diku's float-multiplier format (`1.50` / `0.50`) into clean Go attributes.
2. **Keeper Dialog Messages**:
   - **C Save Routine**: Formats 7 strings terminated by `~` (e.g. keeper lacks item, player lacks item, keeper lacks cash, player lacks cash, keeper won't buy, buy success, sell success).
   - **Go Parser**: Flawlessly reads these dialog blocks, maintaining high-fidelity in-game shopkeeper messages.
3. **Closing Times**:
   - **C Save Routine**: Writes four integers representing opening hour 1, closing hour 1, opening hour 2, and closing hour 2.
   - **Go Parser**: Correctly parses business hours, supporting split shifts (e.g. open morning, close afternoon, open night) exactly as Diku intended.

---

## 3. Go's Architectural Improvements Over C

- **Safe Memory Operations**: In legacy C, updating shop keepers required manual dynamic memory allocations (`CREATE`), string duplications (`str_dup`), and list copying, which frequently led to memory leaks if strings were not freed correctly (`free_shop_strings`). Go's garbage collector completely removes these memory corruption vectors.
- **Protection from Input Hijacking**: OasisOLC Telnet interfaces require capturing builder inputs, checking states, and swapping connection modes, which creates large surface areas for buffer overflow and command hijack exploits. Moving shop configurations offline protects the server.
- **Version Control Integrations**: Storing MUD shops in static `.shp` text files enables easy version tracking via Git, simplifying collaborative world-building.

---

## 4. Concurrency & Thread Safety

- **Read-Only Shop Tables**: Once loaded, shop configurations remain static. Threaded execution routines reading shop prices or checking product lists do not require locks, maximizing throughput.
- **Dynamic Transactions Guarding**: Runtime modifications (such as items added to or sold from shop inventories) are protected via internal Mutexes on the active Shop system, preventing cross-thread inventory corruption.

---

## 5. Summary of Recommended Next Steps

1. **Transition to Modern Serialization**:
   Since the online editor is deprecated, the codebase could eventually migrate legacy Diku `.shp` files to standard JSON or YAML schemas, making offline editing more developer-friendly.
2. **Implement Admin Portal Interface**:
   Expose shopkeepers, inventory lists, and business hours via the modern Dark Pawns `/admin` web portal, enabling builders to modify shops via a visually rich web dashboard rather than legacy terminal menus.
